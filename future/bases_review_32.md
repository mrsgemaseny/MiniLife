# Ревью 32 локальных баз MiniLife

Проверены все JSON в `future/bases Minilife` и его подпапке с базами разбойников. Это ревью данных, а не проверка проходимости в запущенной игре. Все 32 файла имеют размер карты 1000×1000, суммарно содержат 702 362 занятых клетки; у всех `total_blocks` совпадает с фактическим числом записей, координаты находятся в пределах карты.

В JSON записан только токен каждого тайла: `brick`, `dirt`, `door`, `grass`, `pillar`, `stone_floor`, `stone_wall`, `water`, `wheat`, `wood_floor`, `wood_wall`. Типы зданий, склад, ворота крепостной стены, колодец, рабочие места и связь с дорогой за пределами базы **не размечены**. Число зданий по функциям для каждой строки — **не видно**; `door` показывает число тайлов дверей, а не число зданий. «Нет воды» означает только отсутствие токена `water` в самой базе: источник воды может появиться от генератора местности. Все заполненные области лежат внутри карты и не содержат размеченного пути к её краю.

## Сводка и решение для интеграции

- 22 нейтральные или поселковые базы и 10 баз разбойников. В 10 файлах нет токена `door`; в 23 нет `water`; `wheat` есть только в одном файле. Это характеристики **базы**, не доказательство отсутствия таких объектов после процедурной генерации.
- Ни один файл не задаёт тип здания и его услугу. До B2/B6 нужен слой метаданных: `building_id`, функция, вход, зона взаимодействия, запас и владелец. Подмена этих данных числом полов или дверей будет ошибкой.
- Ни одна база не размечает выходящую к краю карты дорогу. При посадке в локальную клетку требуется связать входы базы с дорогами `world.json` или графом дорог; для речных баз нужны также переправы.
- Сначала проверить проходимость стен и дверей, мосты и соединение с дорогой. Большие города на 200–279 тысяч тайлов требуют отдельной проверки времени загрузки и потребления памяти.
- Для точного подсчёта зданий каждого типа требуется аннотированный экспорт PixelBuilder. Пока этот пункт остаётся «не видно» для всех 32 файлов; имена с числом строений не являются проверкой.
