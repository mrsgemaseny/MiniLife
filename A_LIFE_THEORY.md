## 1. Философия A-Life в MiniLife

### 1.1 Что такое A-Life в контексте MiniLife

A-Life (Artificial Life) — это принцип проектирования игрового мира, при котором каждый элемент мира существует независимо от игрока. Мир не "ждёт" игрока. Он живёт сам по себе: фракции расширяются, разбойники грабят деревни, торговцы везут товар, кузнецы умирают, на их место приходят новые люди.

Игрок — это наблюдатель и участник живого мира, а не центр вселенной, вокруг которого всё вращается.

Три главных ориентира для MiniLife:
- **STALKER** — слухи, доски объявлений, поведение группировок без ведома игрока, атмосфера
- **RimWorld** — автономные колонии, логика поведения каждого существа, цепные реакции событий
- **Mount & Blade: Warband** — фракции воюют, захватывают замки, торгуют, живут без вмешательства игрока

Но у MiniLife есть своё уникальное измерение — детектив-нарратив. Игрок не борется со злодеем. Игрок расследует. Мир вокруг него — не просто декорация. Мир — это улика.

### 1.2 Что A-Life НЕ является

A-Life в MiniLife — не симуляция каждой молекулы. Это не Dwarf Fortress с расчётом гидравлики и температуры тела каждого гнома. Это не ультра-реалистичная экономическая модель.

A-Life в MiniLife — это **иллюзия жизни**. Мир должен *выглядеть* живым. Игрок должен *ощущать*, что мир существовал до него и будет существовать после. Это достигается через:

- Конкретные видимые последствия событий (сожжённая деревня, брошенный пост)
- Слухи и информацию, которая распространяется органично
- Фракции с понятной логикой поведения
- NPC с историей и памятью

Производительность — важнее физической точности. Упрощённые модели, работающие быстро — лучше точных моделей, ломающих частоту кадров.

### 1.3 Ключевое разрешение противоречия

Главный вопрос любой A-Life системы: **сколько симулировать?**

Ответ для MiniLife: **два уровня симуляции**.

1. **Детальный (inside bubble)** — всё, что в радиусе ~50 тайлов от игрока. Полная симуляция: позиции, анимации, диалоги, реакция на события.

2. **Глобальный (outside bubble)** — весь остальной мир. Упрощённая симуляция через **цели и события**. NPC не двигается по карте — он "выполняет задачу". Когда игрок приближается, задача материализуется в конкретное поведение.

## 2. Архитектура мировой симуляции

### 2.1 Фундаментальный принцип — дельта симуляции

Мир MiniLife не пересчитывается с нуля при каждом запуске игры. Он имеет **начальное состояние** (сгенерированное из seed) и **накопленные дельты** — изменения, которые произошли в процессе.

Начальное состояние: расположение фракций, деревень, руин, ресурсов — всё детерминировано из seed.  
Дельты: кто умер, какая деревня сожжена, какая фракция потеряла замок, что игрок сделал.

Это означает, что нам не нужно хранить полное состояние каждого NPC. Достаточно хранить **отклонения от начального состояния**.

```
WorldState = seed_state + delta_events[]
```

Каждое значимое событие (смерть лидера, захват города, уничтожение деревни) записывается как дельта с временной меткой. При загрузке игры мир восстанавливается из seed + дельты.

### 2.2 Глобальный тик — соотношение времён

Соотношение: 30 игровых тиков игрока = 1 глобальный тик мира.

Это значит:
- Пока игрок бегает по лесу и рубит деревья, мир делает редкие, крупные шаги
- Один глобальный тик может означать: "разбойники совершили набег на деревню Х"
- Следующий тик (через 30 игровых тиков): "деревня X стала свободной без власти"
- Ещё через несколько тиков: "в деревню пришёл новый торговец"

Такой подход даёт ощущение живого мира без вычислительного ада.

Частота глобального тика должна быть переменной:
- В спокойное время — редкие тики (события фоновые, малозначимые)
- В период войны — частые тики (линии фронта двигаются)
- В кризис (нападение на столицу, смерть короля) — несколько тиков подряд

### 2.3 Bubble — три уровня LOD

Simulation Bubble — это концентрические кольца вокруг игрока с разным уровнем детализации:

**Уровень 1 — Полная симуляция (radius < 50 тайлов)**  
- Каждый NPC обновляется каждый кадр
- Полный pathfinding через A*
- Диалоги, анимации, реакция на звуки
- Боевая механика в реальном времени

**Уровень 2 — Упрощённая симуляция (50-100 тайлов)**  
- Обновление раз в 5 секунд
- NPC "тикает" по состояниям: patrol → idle → respond
- Без детализации анимации
- Цели выполняются как переходы состояний

**Уровень 3 — Глобальная симуляция (> 100 тайлов)**  
- Обновление раз в 30 секунд
- NPC существует как запись в глобальной таблице агентов
- У него есть: текущая цель, текущая подцель, прогресс
- Без позиции в пространстве — только логическое состояние

При приближении игрока уровень LOD повышается — NPC "материализуется" в правильном месте относительно своей цели.

### 2.4 Персистентность мира между сессиями

Мир живёт когда игрок не играет? Нет — мир не симулируется в отсутствие игрока. Но при следующем запуске игры происходит **catch-up симуляция**:

При загрузке:
1. Вычисляется прошедшее реальное время с последнего сеанса
2. Это время переводится в количество глобальных тиков
3. Ускоренная симуляция выполняет эти тики один за другим
4. Применяются дельты

Ограничение: catch-up не безграничный. Максимум — эквивалент 7 игровых дней. Если игрок не заходил месяц, мир не симулировал месяц — он сделал не более 7 дней.

Это важно с точки зрения нарратива: мир не уходит слишком далеко в непредсказуемые состояния.

## 3. Система тиков и LOD

### 3.1 Структура глобального агента

Каждый NPC вне bubble существует как `GlobalAgent` — упрощённая запись:

```gdscript
class GlobalAgent:
    var agent_id: int
    var faction_id: int
    var settlement_id: int       # к какому поселению принадлежит
    var role: AgentRole          # GUARD / MERCHANT / BANDIT / SOLDIER / CIVILIAN
    var current_goal: AgentGoal  # глобальная цель
    var current_subgoal: AgentSubgoal
    var goal_progress: float     # 0.0 - 1.0
    var memory_flags: Dictionary # что он знает о мире
    var relation_to_player: int  # -100 до +100
    var is_alive: bool
```

При глобальном тике каждый агент проверяет свою цель и двигает `goal_progress`.

### 3.2 Иерархия целей глобального агента

Глобальные цели (верхний уровень):
- `DEFEND_SETTLEMENT` — охранять поселение
- `PATROL_REGION` — патрулировать регион
- `TRADE_ROUTE` — торговать между поселениями
- `RAID_TARGET` — атаковать цель (деревня, игрок)
- `RETREAT_TO_SAFETY` — отступить при поражении
- `REINFORCE_ALLY` — помочь союзнику

Подцели (нижний уровень) разворачиваются при встрече с игроком:
- Агент с `PATROL_REGION` → при bubble-контакте: идёт по маршруту, останавливается, оглядывается, реагирует на игрока
- Агент с `RAID_TARGET` → при bubble-контакте: атакует, кричит, убегает при поражении

### 3.3 Материализация при приближении игрока

Когда игрок входит в radius ≤ 100 тайлов от агента:

1. Глобальный агент получает физические координаты (рассчитываются исходя из его `goal_progress`)
2. Создаётся Entity в сцене
3. Entity получает состояние из `GlobalAgent` (цель, отношение к игроку, память)
4. Начинается полная симуляция

При выходе из bubble — обратный процесс: физическая Entity удаляется, `GlobalAgent` обновляется.

## 4. NPC-агенты — иерархия целей

### 4.1 Классификация NPC

В мире MiniLife существуют три крупных класса NPC:

**Уникальные NPC (400+ персонажей)**  
У каждого из них есть имя, история, роль в лоре. Они могут быть лордами, торговцами, рыцарями, монахами, убийцами. Некоторые критически важны для основного нарратива — расследования падения империи. Они хранятся отдельно с полным набором данных.

**Именованные NPC (рандомайзер)**  
Генерируются из пулов имён и роли. Каждый кузнец, трактирщик, командир стражи имеет имя. Но их история — процедурная. Если кузнец умирает — его место занимает новый именованный NPC.

**Фоновые NPC (массовка)**  
Деревенские жители, солдаты в рядах армии, бандиты в лагерях. Без имён, только роли. Они создают толпу, атмосферу, численность. При гибели просто исчезают.

### 4.2 Полное NPC-состояние (внутри bubble)

```gdscript
class NPC extends CharacterBody2D:
    # Идентификация
    var npc_id: int
    var display_name: String
    var is_unique: bool
    
    # Социальный статус
    var faction_id: int
    var role: NPCRole
    var social_rank: int         # 0=peasant, 10=king
    
    # Отношения
    var relation_to_player: int  # -100 до +100
    var known_player_reputation: float  # насколько знает о репутации игрока
    var grudge_flags: Array[int] # id событий, за которые держит злобу
    
    # Память
    var memory_events: Array[MemoryEvent]  # что видел, слышал
    var heard_rumors: Array[RumorEntry]    # слухи
    
    # Поведение
    var ai_state: NPCState
    var current_goal: NPCGoal
    var home_position: Vector2
    var patrol_route: Array[Vector2]
    
    # Боевые параметры
    var morale: float            # 0.0-1.0, при низком — отступает
    var equipment_tier: int      # T1-T6
```

### 4.3 Дневные и ночные рутины

День/ночь влияет на поведение всех NPC:

**Дневные рутины:**
- Торговцы открывают лавки (08:00 - 20:00 игрового времени)
- Кузнецы работают
- Стража патрулирует в полном составе
- Фермеры на полях

**Ночные рутины:**
- Деревни закрываются. Ворота заперты.
- Большинство NPC переходят в состояние `SLEEP`
- Охрана сокращается в 4 раза — только ночная стража
- Таверны работают (ночной контингент — особый)
- Разбойники активнее ночью — атаки чаще

Ночная атака на деревню имеет иные шансы, чем дневная. Это создаёт реальный тактический выбор.

### 4.4 Моральная система — когда NPC убегает

NPC не сражается до смерти бездумно. У каждого есть параметр `morale` (мораль).

Мораль снижается при:
- Потере союзников рядом (видит, как падает товарищ)
- Получении урона (трусость зависит от роли)
- Численном превосходстве противника
- Убийстве командира группы

При мораль < порога NPC переходит в `FLEE` — убегает от боя.

Факторы, повышающие мораль:
- Союзники рядом (чем больше — тем выше)
- Командир жив
- Высокое снаряжение
- Фанатики (стражи культа, личная гвардия лидера) — повышенный порог страха

Для игрока это важно: если убить командира группы врагов — остальные могут разбежаться.

### 4.5 Реакция на гибель

Когда NPC видит труп рядом (в радиусе реакции):

Вариант по роли:
- `CIVILIAN` → паника, побег, крик (привлекает стражу)
- `GUARD` → переход в боевую готовность, обследование трупа
- `BANDIT` → насторожённость, могут мародёрствовать
- `MERCHANT` → паника, бегство к ближайшему посту

Это создаёт интересные тактические ситуации. Игрок, убивший кого-то незаметно, получает время до обнаружения. Открытое убийство мирного в деревне немедленно поднимает тревогу.

## 5. Память и взаимодействие NPC

### 5.1 Что NPC помнит о игроке

NPC помнит игрока только при **прямом взаимодействии**:
- Разговор
- Бой
- Торговля
- Игрок совершил действие в их присутствии (убил кого-то, помог)

Случайный NPC, мимо которого игрок прошёл — ничего не запоминает.

Память хранится как список `MemoryEvent`:

```gdscript
class MemoryEvent:
    var event_type: MemoryType   # MET / TRADED / HOSTILE / HELPED / WITNESSED
    var timestamp: int           # игровое время
    var player_context: String   # краткое описание контекста
    var sentiment: int           # -2 до +2
```

Эта память влияет на диалог. NPC, которому игрок помог месяц назад, может напомнить об этом.

### 5.2 Злоба — постоянная отметина

Если игрок убил кого-то важного для NPC (друга, напарника, командира) — это записывается как `GRUDGE_FLAG`. Это **постоянно**. NPC не забывает.

Уровни злобы:
- **Слабая злоба** — NPC недружелюбен, цены хуже, отказывается от квестов
- **Средняя злоба** — NPC отказывается общаться, предупреждает других
- **Сильная злоба** — NPC может нанять убийц или лично атаковать при встрече
- **Кровная месть** — только у уникальных NPC; активная охота на игрока

Пример: игрок убил командира стражи деревни X. Среди стражников был его брат (уникальный NPC). Теперь этот NPC — враг навсегда, независимо от репутации.

### 5.3 Слухи между NPC

NPC не делятся информацией с другими NPC в реальном времени. Но существует механизм **случайных разговоров** (как в STALKER):

При встрече двух NPC в одной сцене (или на одной площади) с определённой вероятностью происходит обмен "слухом". Это не диалог для игрока — это фоновый процесс. NPC X получает в свою `heard_rumors` запись от NPC Y.

Игрок может подслушать такой разговор если находится рядом.

Слухи передаются медленно. Информация из далёкого города доходит через цепочку NPC — занимает несколько игровых дней. Это создаёт ощущение органичного распространения новостей.

### 5.4 Доска объявлений — агрегатор событий

В каждом значимом поселении есть доска объявлений (как в STALKER "доска с информацией"). На ней:

- Объявления о пропавших людях
- Рассказы о событиях в регионе ("Разбойники сожгли деревню Кель")
- Наградные грамоты (в том числе на игрока при определённой репутации)
- Торговые объявления
- Слухи и сплетни

Доска обновляется по глобальным тикам. Это живой журнал мира — игрок, читая его в разных городах, собирает картину происходящего.

## 6. Фракционная система

### 6.1 Типология фракций

В мире MiniLife существует минимум 8 крупных фракций. Каждая — отдельная сущность с территорией, идеологией, экономикой и армией.

**Типы фракций:**

1. **Королевства / Герцогства** — территориальные государства с армией, налогами, замками. Основная политическая сила. Минимум 4-5 таких фракций.

2. **Свободные города** — богатые торговые центры без единого правителя. Управляются советом торговцев. Нейтральны в большинстве войн, но могут нанять армию.

3. **Церковь** — религиозная организация по образцу Norland. Имеет свои поселения (монастыри, соборы), паству, политическое влияние. Может объявлять крестовые походы или благословлять войны.

4. **Гильдии** — профессиональные объединения. Гильдия торговцев, гильдия наёмников, гильдия ремесленников. Не имеют территории но имеют сети представительств в городах.

5. **Разбойничьи кланы** — организованные бандиты с лагерями, иерархией, целями.

6. **Дезертиры** — отдельная серая зона (см. раздел 19).

### 6.2 Структура фракции

```gdscript
class Faction:
    var faction_id: int
    var name: String
    var faction_type: FactionType
    var ideology: FactionIdeology
    
    # Территория
    var capital_settlement_id: int
    var controlled_settlements: Array[int]
    var claimed_territory: Array[Vector2i]  # чанки
    
    # Ресурсы
    var treasury: int
    var military_strength: int   # абстрактная военная мощь
    var economic_output: int     # ежетиковый доход
    
    # Дипломатия
    var relations: Dictionary    # faction_id -> int (-100 до +100)
    var active_wars: Array[int]  # id фракций, с которыми идёт война
    var treaties: Array[Treaty]  # торговые договора, перемирия
    
    # Лидер
    var leader_id: int           # уникальный NPC
    var succession_list: Array[int]  # кто следующий
```

### 6.3 Идеология фракции

У каждой фракции есть идеология, которая определяет её поведение:

- **Экспансионизм** — агрессивное расширение территорий, частые войны
- **Торговля** — минимизация войн, максимизация торговых маршрутов
- **Изоляционизм** — защита своей территории, нейтралитет
- **Религиозный фанатизм** — агрессия к еретикам, крестовые походы
- **Бандитизм** — рейды, грабёж, без дипломатии

Идеология влияет на решения в глобальных тиках: когда объявлять войну, когда заключать мир, как реагировать на действия игрока.

### 6.4 Автономное поведение фракции

На каждый глобальный тик каждая фракция выполняет `FactionTick()`:

```
FactionTick():
  1. Оценить военную угрозу (есть ли враги у границ?)
  2. Оценить экономическое состояние (treasury выше порога?)
  3. Проверить дипломатические отношения (есть ли повод для войны/мира?)
  4. Принять решение (атака / защита / торговля / ничего)
  5. Отдать приказы военным агентам
  6. Обновить treasury (экономические тики)
```

Фракции действительно расширяются, захватывают нейтральные деревни, воюют и торгуют без участия игрока.

---

## 7. Смерть лидера и распад фракции

### 7.1 Что происходит при гибели лидера

Лидер фракции — уникальный NPC. Если он погибает (от рук игрока, от рук врагов, от случайного события) — запускается `LeaderDeathEvent`.

Последствия разворачиваются через несколько глобальных тиков:

**Тик 1:** Смерть объявлена. Фракция входит в состояние `SUCCESSION_CRISIS`.  
**Тик 2-3:** Города и замки оценивают список наследников. Часть лордов поддерживает наследника A, часть — наследника B.  
**Тик 4:** Если наследник один и признан — плавная передача власти. Если претендентов несколько — гражданская война.  
**Тик 5+:** На бывших территориях фракции резко растёт число разбойников и дезертиров. Часть поселений объявляет независимость.

### 7.2 Варианты исходов

**Сценарий 1: Плавное наследование**  
Признанный наследник берёт власть. Фракция теряет ~15% военной мощи (смута), но остаётся единой. Игрок может этим воспользоваться — атаковать ослабленную фракцию.

**Сценарий 2: Гражданская война**  
Два претендента делят армию. Начинается внутренний конфликт. Граница фракции перестаёт расширяться, территория может сократиться. Враги пользуются моментом.

**Сценарий 3: Распад**  
Если лидер умер и нет признанного наследника — фракция распадается на независимые города-государства. Каждый город теперь сам по себе. Это освобождает огромные территории.

**Сценарий 4: Поглощение**  
Более сильная соседняя фракция может предъявить права на "бесхозные" земли и аннексировать часть городов.

### 7.3 Столица — ключевой узел

У каждой фракции есть столица. Столица — самый укреплённый и богатый город. Захват столицы = смена власти над всей фракцией.

Это создаёт понятную военную логику: войны заканчиваются захватом столицы, а не уничтожением каждого солдата.

---

## 8. Торговля и межфракционные отношения

### 8.1 Торговля между фракциями

Фракции торгуют друг с другом если выполнены условия:
- Отношения > -20 (не в состоянии войны)
- Существует торговый маршрут (дорога или нейтральная территория)
- У обеих есть что предложить

Торговля влияет на отношения — чем больше торгуют, тем лучше отношения (медленно). Перекрытие торговых маршрутов (в том числе игроком) ухудшает отношения.

### 8.2 Дипломатические состояния

Между каждой парой фракций существует одно из состояний:
- `WAR` — активный конфликт
- `HOSTILE` — плохие отношения, без активных действий
- `NEUTRAL` — безразличие
- `TRADE_PACT` — торговый договор
- `ALLIANCE` — военный союз
- `TRUCE` — временное перемирие (с таймером)

Перемирие может закончиться — тогда война возобновляется.

### 8.3 Как фракция объявляет войну

Решение об объявлении войны принимается по `casus belli` — поводу:
- Агрессия против подданных
- Захват торгового каравана
- Религиозные разногласия
- Пограничный спор
- Оппортунизм (когда враг слаб)

Без повода война не объявляется — это делает поведение фракций читаемым и логичным. Игрок может создать `casus belli` намеренно.

# ЧАСТЬ V: ЭКОНОМИКА

## 9. Экономика поселений

### 9.1 Типология поселений по экономике

Экономика в MiniLife не симулирует глобальные рынки. Она работает на уровне поселений.

Каждое поселение имеет:
- `production_goods[]` — что производит
- `demand_goods[]` — что нужно
- `treasury` — золото поселения
- `prosperity_level` — уровень процветания (1-5)

Цены зависят от типа поселения:

| Тип | Еда | Оружие | Роскошь |
|---|---|---|---|
| Деревня | дёшево | дорого | очень дорого |
| Торговый город | средне | средне | средне |
| Крепость | дорого | дёшево | дорого |
| Столица | дорого | средне | средне |

Это создаёт органичный торговый стимул: покупать еду в деревне, продавать в крепость; покупать оружие в крепости, продавать в деревню.

### 9.2 Процветание поселения

`prosperity_level` (1-5) влияет на:
- Ассортимент товаров
- Качество снаряжения у стражи
- Число жителей (атмосферно)
- Устойчивость к разбойничьим набегам

Процветание растёт при:
- Регулярных торговых маршрутах
- Уничтожении ближайших разбойничьих лагерей (квест-цепочки)
- Мире в регионе

Процветание падает при:
- Набегах разбойников
- Войне в регионе
- Блокаде торговых маршрутов
- Голоде (истощение ресурсов при долгой осаде)

### 9.3 Голод — крайнее состояние

Голод возникает когда поселение теряет поставки еды на несколько тиков подряд:
- Осада без снятия
- Вырезаны все торговые маршруты
- Катастрофический неурожай (событие)

Последствия голода:
- Стража ослабевает (мораль вниз)
- Жители бегут из деревни
- Поселение легче захватить

Голод — инструмент осадной войны.

### 9.4 Влияние игрока на экономику

Игрок не торгует в масштабе, влияющем на весь рынок. Но:

- Уничтожение разбойничьего лагеря → близлежащая деревня получает +1 к процветанию через несколько тиков
- Выполнение цепочки квестов на восстановление → поселение может вырасти
- Массовое убийство стражи → резкое падение безопасности, рост разбойников
- Игрок как охранник каравана → успешная торговая операция

## 10. Система каравана

### 10.1 Как работают торговые маршруты

Реальный pathfinding для каждого каравана — слишком дорогой. Вместо этого используется **процентная модель успешности**:

При каждом глобальном тике для каждого активного торгового маршрута рассчитывается:

```
success_chance = base_chance
  - regional_bandit_density * BANDIT_PENALTY
  - war_in_region * WAR_PENALTY
  + road_quality * ROAD_BONUS
  + trade_guards_hired * GUARD_BONUS
```

Результат — бросок кубика с этим шансом.

**Успех:** Торговля состоялась. Оба поселения получают товары. Казна обоих растёт.

**Неудача:** Кризис на маршруте. Выбирается одно из событий:
- Нападение разбойников (может встретить игрок)
- Плохая дорога, задержка
- Болезнь в каравана
- Непогода

### 10.2 Встреча игрока с караваном

Несмотря на то что каравана не двигается по карте в реальном времени, **игрок может встретить его**. Как это работает:

Если у маршрута A→B игрок находится физически на дороге между A и B в момент когда маршрут активен — с определённой вероятностью появляется физический Entity каравана.

При **успешном маршруте**: мирный торговый обоз. Можно поговорить с купцами, купить редкие товары (успешный маршрут часто везёт экзотику).

При **неуспешном маршруте (атака)**: игрок может застать нападение в процессе. Помочь → награда от торгового поселения и гильдии, уникальные предметы из каравана, репутация.

Это даёт ощущение живого мира без симуляции каждой телеги.

### 10.3 Гильдия торговцев как фракция

Гильдия торговцев контролирует большинство маршрутов. Высокий статус в гильдии означает:
- Лучшие цены
- Информация о выгодных маршрутах
- Квесты на охрану/разведку
- Эксклюзивные товары

Если в регионе слишком много нападений на маршруты — гильдия нанимает охранников или перекрывает маршрут. Это ухудшает экономику региона.

# ЧАСТЬ VI: КОНФЛИКТЫ И ВОЙНЫ

## 11. Конфликты и войны

### 11.1 Уровни конфликта

Конфликт в MiniLife существует на трёх уровнях:

**Микро-уровень:** Отдельные столкновения — разбойники напали на путника, солдаты подрались в таверне. Это ежедневные события, не меняющие политическую карту.

**Мезо-уровень:** Набеги на поселения, осады небольших постов. Разбойничьи кланы против деревень. Меняет состояние конкретных поселений.

**Макро-уровень:** Войны между фракциями. Меняет политическую карту, двигает границы, может уничтожать фракции.

### 11.2 Механика войны

Когда две фракции объявляют войну:

1. Каждая фракция получает `war_stance` — агрессивная или оборонительная
2. По глобальным тикам рассчитываются военные операции:
   - Кто атакует какое поселение
   - Чья армия сильнее в точке конфликта
   - Результат битвы
3. Проигравшая сторона теряет контроль над поселением
4. Война заканчивается при:
   - Захвате столицы
   - Полном уничтожении военной мощи одной стороны
   - Запросе мира (казна < порога, военная мощь < порога)

### 11.3 Генеральные сражения

Возможный расширенный вариант — **генеральные сражения**: событие, при котором две крупные армии встречаются на поле боя.

При таком событии:
- Создаётся специальная сцена (поле боя)
- Игрок может присоединиться к одной из сторон
- Исход битвы влияет на весь ход войны

Это редкое событие, но когда оно происходит — оно ощущается как важный момент истории мира.

### 11.4 Линии фронта

Политическая карта мира — живая. Захваченные поселения меняют цвет на карте. Линии фронта двигаются.

Игрок может в любой момент открыть карту и видеть актуальное состояние политической ситуации. Это даёт информацию: куда идти, кто слаб, где возможности.

## 12. Осады и судьба поселений

### 12.1 Механика осады

Разбойничьи кланы и вражеские фракции могут осаждать поселения. Стандартная осада длится 1 игровой день.

Этапы осады:
1. **Окружение** — нападающие окружают поселение, перекрывая торговые пути
2. **Штурм** — атака на ворота и стены
3. **Исход** — либо поселение отбивается, либо захватывается

Факторы влияющие на исход:
- Военная мощь нападающих vs. гарнизон поселения
- Уровень укреплений поселения
- Помощь союзников
- Участие игрока

### 12.2 Запрос помощи

Если поселение находится в осаде — оно может послать гонца за помощью. Это выражается как:

- Квест на доске объявлений соседних городов ("Деревня X осаждена!")
- Прямое обращение NPC к игроку если он находится рядом

Таймер: у игрока есть ограниченное время. Если опоздать — осада завершилась без него.

### 12.3 Три исхода судьбы поселения

После осады поселение может оказаться в одном из трёх состояний:

**1. Разорённая деревня** — нападавшие ушли после грабежа, не заняв. Поселение существует, но разрушено. Жители напуганы, торговцы ушли, защита слабая. Через несколько тиков начинается восстановление (медленное).

**2. Свободная деревня / без власти** — предыдущий хозяин изгнан, новый не пришёл. Поселение функционирует, но без официального управления. Более высокий уровень преступности, нестабильные цены, нет квестов от власти.

**3. Руины** — полное уничтожение. Здания разрушены, жителей нет. Через долгое время зарастает растительностью. Могут стать точкой интереса с историческими артефактами.

Эти три исхода создают органичную историю на карте. Игрок, вернувшийся через несколько игровых дней, может увидеть изменения.

# ЧАСТЬ VII: РЕПУТАЦИЯ И ПАМЯТЬ

## 13. Репутация игрока

### 13.1 Два вектора репутации

У игрока в MiniLife существуют **два независимых параметра репутации**:

**Мировая репутация** — известность в масштабах всего мира.  
Изначально: 0 (ты никто). Никто о тебе не слышал.  
Растёт с: крупными действиями, влияющими на фракции и политику.  
При высоком значении: уникальные NPC знают тебя до знакомства. Некоторые разбойники не трогают.

**Региональная / фракционная репутация** — известность в конкретном регионе или у конкретной фракции.  
Гораздо легче набрать и потерять.  
Влияет на: цены, доступность квестов, отношение стражи, количество атак.

### 13.2 Динамика мировой репутации

Мировая репутация растёт медленно и требует значимых действий:

| Действие | Прирост репутации |
|---|---|
| Убийство обычного разбойника | +0 |
| Спасение осаждённой деревни | +5 |
| Убийство лидера разбойничьего клана | +10 |
| Победа в генеральном сражении | +25 |
| Убийство лидера фракции | +/-30 (зависит от контекста) |
| Уничтожение крупной фракции | +50 |

При мировой репутации > порога:
- NPC могут узнавать игрока при первой встрече ("Говорят, ты тот путник из...")
- Некоторые разбойники T1-T2 не атакуют (слишком опасно)
- Квесты высокого уровня открываются

### 13.3 Отрицательная репутация

Репутация может быть отрицательной — известность как злодея, убийцы, врага.

При отрицательной мировой репутации:
- Большинство мирных NPC избегают игрока
- Стража атакует без провокации
- Разбойники могут СОЮЗНИЧАТЬ с игроком (враг врага)
- Определённые квесты открываются (тёмные цепочки)
- Уникальные NPC могут нанять убийц

### 13.4 Репутация и экипировка

Интересная механика: игрок в ужасном снаряжении T1 не воспринимается как угроза, даже с высокой репутацией в беседе. Визуальный образ имеет значение.

При высоком уровне снаряжения + высокой репутации — разбойники T1 и T2 вообще не атакуют. Нет смысла нападать на того, кто явно сильнее.

## 14. Мировая память и слухи

### 14.1 Система слухов

Слухи — это инструмент обратной связи: игрок совершил что-то важное, мир начинает об этом говорить.

Слух имеет:
- `content` — суть события ("Путник сжёг деревню", "Герой спас торговый пост")
- `origin_location` — откуда пошёл слух
- `spread_radius` — насколько далеко разошёлся
- `distortion_level` — насколько искажён (чем дальше — тем больше)

Слухи распространяются через:
1. Доски объявлений (быстро в крупных городах)
2. Торговые маршруты (средне, через гильдии)
3. Случайные разговоры NPC (медленно, локально)
4. Гонцы фракций (быстро, целевая аудитория)

### 14.2 Искажение слухов

Слухи на расстоянии искажаются. Это намеренная механика:

Событие: "Игрок спас деревню от 10 разбойников"  
- В соседней деревне: "Путник убил разбойников"  
- В городе (2 региона): "Герой в одиночку разбил банду в 30 человек"  
- В столице (5 регионов): "Легендарный воин уничтожил целый клан разбойников"

Искажение создаёт комедийные/драматические ситуации. Игрок может услышать раздутую версию своего собственного подвига.

Это также применимо к детектив-нарративу: разные люди знают разные версии одних и тех же событий вокруг падения империи.

### 14.3 Мировые события — хроника

Значимые события фиксируются в **мировой хронике** — внутренняя запись игры:

```gdscript
class WorldEvent:
    var event_id: int
    var event_type: WorldEventType
    var timestamp: int
    var location: Vector2i
    var participants: Array[int]   # faction/npc ids
    var outcome: String
    var is_public: bool            # видно игроку на доске?
```

Публичные события появляются на досках объявлений. Непубличные — только в диалогах у конкретных NPC (они "случайно" упоминают).

Игрок может изучить хронику через: доски объявлений, разговоры, записки в руинах, дневники NPC.

# ЧАСТЬ VIII: ДЕТЕКТИВ-НАРРАТИВ

---

## 15. Детектив-нарратив — расследование падения империи

### 15.1 Фундамент: мир без императора

Игра начинается в мире, который уже рухнул. Молодой император мёртв — месяц назад. Империи больше нет. Есть осколки: бывшие имперские провинции, теперь самопровозглашённые королевства. Бывшие вассалы, делящие территорию. Бывшая столица — либо руины, либо спорный город.

Игрок — никто. Путник, пришедший в этот мир. Без истории, без фракции, без репутации.

Центральный вопрос: **кто убил императора и почему?**

Это не квест с маркером. Это расследование — постепенное накопление информации через весь игровой процесс.

### 15.2 Четыре версии событий

В мире существуют четыре версии гибели империи, которые распространены среди разных групп населения:

**Версия 1: Внешний враг**  
Одна из соседних держав организовала заговор. Убийца — наёмник, нанятый иностранным лордом.

**Версия 2: Внутренний заговор**  
Имперские вассалы убили молодого императора сами — он слишком активно реформировал власть.

**Версия 3: Религиозный фанатизм**  
Церковная организация убила императора за еретические взгляды и реформы.

**Версия 4: Личная месть**  
Убийство не политическое — личная история. Конкретный человек с конкретной причиной.

**Одна из них — правда.** Остальные три — частично верны, частично сфабрикованы, частично случайные совпадения.

### 15.3 Убийца — фиксированный персонаж

Убийца — конкретный NPC из списка 400+ уникальных персонажей. Не рандомная генерация — фиксированный лор.

Убийца:
- Живёт в мире, занимается своими делами
- Не знает что игрок расследует
- Имеет собственные цели и маршруты
- Может быть опасным противником
- Может быть человеком из неожиданного места

### 15.4 Детективный процесс — как игрок расследует

Расследование не линейно. Нет "следующего маркера". Есть слои информации:

**Слой 1 — Слухи (везде)**  
Любой NPC может сказать что-то о смерти императора. Большинство знает только общую версию.

**Слой 2 — Свидетели (конкретные NPC)**  
Некоторые уникальные NPC были при дворе, видели или слышали что-то важное. Чтобы поговорить с ними — нужно их найти и заслужить доверие.

**Слой 3 — Документы (руины, архивы)**  
В мире рассеяны документы: письма, дневники, официальные бумаги. Часть в руинах, часть у коллекционеров, часть охраняется фракциями.

**Слой 4 — Прямые улики (конкретные места)**  
Место гибели, личные вещи императора, скрытые комнаты во дворце — прямые улики для опытного следователя.

### 15.5 Противоречивые показания — намеренно

Разные свидетели дают разные версии. Это не баг — это механика. Каждый видел часть картины. Некоторые лгут (из страха, из корыстных целей). Некоторые искренне заблуждаются.

Игрок собирает фрагменты и сам формирует вывод. Игра не объявляет "ты нашёл правильный ответ" — игрок принимает решение основываясь на собранных доказательствах.

### 15.6 Три финала и один тайный

**Финал 1-3** — основаны на версиях 1-3. Игрок пришёл к одной из неполных версий, обвинил конкретного человека или фракцию. Последствия разные.

**Финал 4 (тайный)** — игрок нашёл всю цепочку до конца. Правда. И в конце этой цепочки — не просто убийца, а понимание: за убийством стоит нечто большее. Демон, который работал через людей. Именно здесь открывается истинная природа происходящего.

Тайный финал ведёт к возможности сразиться с самим демоном — сущностью, о которой буквально никто в мире не знает. Это не злодей из очевидной угрозы. Это скрытая ось всего произошедшего.

## 16. Убийца императора — нарративная механика

### 16.1 Демон как нарративный центр

Про демона буквально никто не знает. Нет "проклятия" на всём мире, нет очевидных признаков. Есть только один след — в личных записях мёртвого императора.

Это означает:

- Демон не является "финальным боссом" в классическом смысле
- Он не нападает на деревни, не двигает армии
- Он действовал через людей — убийца была инструментом
- Его существование — тайна, которую игрок открывает в самом конце

Для 99% NPC в мире демон не существует. Они знают только политическую версию событий.

### 16.2 Что делать с убийцей

Когда игрок находит убийцу:

Вариант A: Убить  
Месть совершена. Но правда не обязательно открыта. Кто стоит за убийцей?

Вариант B: Поговорить  
Убийца может знать больше. Возможно, она сама не знала о демоне.

Вариант C: Предать суду  
Если у игрока есть союзная фракция — можно передать убийцу для суда. Политические последствия.

Вариант D: Проигнорировать  
Игрок может выйти на убийцу и решить, что это не важно. Продолжать жить в мире.

Игра не навязывает путь.

## 17. Экосистема

### 17.1 Животные как фоновый слой

Животные в MiniLife — не сложная симуляция популяций. Они создают:
- Атмосферу биома (волки в тёмном лесу, олени в долинах)
- Ресурсный источник (шкуры, мясо, кости)
- Угрозу (хищники)
- Тактические ситуации (волчья стая, медведь в берлоге)

Птицы — чистая атмосфера. Без состояний, без целей. Анимация + звук.

### 17.2 Хищники и жертвы

Хищники реально охотятся на травоядных в мире. Это создаёт органичное движение на карте.

Механика: Волки имеют `HUNT` как глобальную цель. При bubble-контакте — материализуются в охоте. Игрок может увидеть погоню.

Популяция не симулируется динамически — она периодически регулируется через `respawn_timer`. Если охотник убил много волков — новые появятся не сразу, с задержкой. Это даёт ощущение истощения популяции без сложной симуляции.

### 17.3 Альфа хищников

У волчьей стаи есть альфа. Убийство альфы рассеивает стаю — остальные переходят в `FLEE` или `ROAM`.

Визуально: альфа чуть крупнее, возможно с уникальной меткой.

Это применимо к медведям, крупным кабанам — боссам локальной фауны.

### 17.4 Ночная фауна

Некоторые виды активны только ночью. Это создаёт разную опасность по времени суток:

- День: стандартная фауна
- Ночь: появляются ночные хищники, более агрессивные

В регионах с высокой популяцией волков — по ночам слышен вой (атмосферный звук зависит от фауны региона).

### 17.5 Ресурсная регенерация

Ресурсы (деревья, руда, животные) бесконечны глобально, но локально истощаются. `respawn_timer` длиннее для редких ресурсов, короче для обычных.

Срубленный лес начнёт восстанавливаться — процесс долгий. Это создаёт смысл в разнообразии перемещений.

# ЧАСТЬ X: РАЗБОЙНИКИ И ДЕЗЕРТИРЫ

## 18. Разбойники и серая зона

### 18.1 Классификация "плохих парней"

В MiniLife нет единой категории "враг". Есть спектр:

**Разбойники** — организованные преступные кланы с лагерями, иерархией, экономикой. Нападают на деревни и торговцев системно.

**Дезертиры** — бывшие солдаты, бежавшие с войны. Опасны но не организованы. Часто одиночки или малые группы. Историчны — за каждым есть история.

**Беглецы** — мирные жители, бежавшие от войны. Не агрессивны, но могут стать разбойниками при отчаянии.

**Наёмники без контракта** — военные профессионалы без работы. Нейтральны пока не найдут нанимателя.

### 18.2 Дезертиры — отдельная глубина

Дезертир — персонаж с историей. Он покинул армию (или был вынужден). Причины разные:

- Убеждения (не хотел воевать в несправедливой войне)
- Страх (сбежал после поражения)
- Предательство (его предали, он отомстил)
- Личная история (семья в опасности)

С дезертиром можно говорить. Его история — кусок мировой хроники. Некоторые дезертиры вплетены в детектив-нарратив.

### 18.3 Переход из разбойников в мирные

Это открытый вопрос из анкеты. Несколько механик:

**Вариант А: Время и отсутствие жертв**  
Если разбойник не совершал нападений долгое время и не находится рядом с активными бандами — он медленно "дрейфует" к нейтральному статусу. Через долгое время может поселиться в деревне как обычный NPC.

**Вариант Б: Квест-изменение**  
Игрок может дать разбойнику шанс. Конкретный квест (помочь найти работу, оплатить долг, помочь с проблемой) переводит конкретного NPC из `BANDIT` в `CIVILIAN`.

**Вариант В: Амнистия фракции**  
При определённых условиях (смена власти, конец войны, особый указ) фракция может объявить амнистию. Часть дезертиров и мелких разбойников легализуется.

### 18.4 Разбойничьи кланы — структура

Разбойничий клан — не просто лагерь врагов:

```
Клан:
  - Вожак (уникальный или именованный NPC)
  - Lieutenants (2-3 именованных NPC)
  - Рядовые (фоновые NPC)
  - Лагерь (физическая точка на карте)
  - Территория контроля (регион набегов)
  - Казна (накапливается от набегов)
```

Уничтожение вожака дестабилизирует клан. Lieutenants могут попытаться взять власть или разбежаться. Уничтожение всех Lieutenants разрушает клан — рядовые рассеиваются.

# ЧАСТЬ XI: АТМОСФЕРНЫЕ СИСТЕМЫ

## 19. Атмосферные системы

### 19.1 Философия атмосферы

Атмосфера — это не симуляция. Это сигналы, которые мозг игрока интерпретирует как "живой мир".

Список атмосферных элементов:
- Птицы (без AI, чистая анимация + звук)
- Следы на земле (снег/грязь, декоративные)
- Звуки региона (волки, ветер, насекомые зависят от биома и времени суток)
- Вороны (как событийный триггер над местами гибели)
- Мародёры у трупов (в определённых регионах)

### 19.2 Следы как атмосфера и намёк

Следы на земле (снег, грязь) — не симуляция передвижения. Это:

- Декоративный элемент у часто посещаемых мест (тропа к колодцу)
- Местный детектив-намёк: "кто-то прошёл здесь недавно"
- Региональное движение: следы большой группы ведут к лагерю разбойников

### 19.3 Вороны

Вороны — атмосферный триггер:

- Над свежим полем боя → вороны кружатся (2-3 часа игрового времени после события)
- Над руинами с трупами → постоянные вороны
- Игрок видит вороны вдалеке → сигнал: там что-то случилось, стоит исследовать

Это органичный указатель на события без HUD-маркеров.

### 19.4 Звуковой дизайн A-Life

Звук — важнейший атмосферный инструмент:

- В лесу с высокой популяцией волков: вой слышен ночью (без видимого существа)
- Рядом с деревней в осаде: далёкие крики, звон металла
- После набега: тишина, редкие звуки
- У активного разбойничьего лагеря: голоса, смех, звон монет

Звуки региональные — привязаны к биому, времени суток, текущим событиям.

## 20. Производительность и техническая реализация

### 20.1 Оценка объёма

Размер мира и количество агентов:
- Карта: 1000x1000 тайлов (теоретический максимум в 1 сессии — обычно меньше)
- Поселения: ~30-50 на карту (деревни + города + крепости + замки)
- NPC на карту: 15-400 NPC per поселение × 50 поселений = потенциально 7500-20000 NPC

Это много. Большинство из них — `GlobalAgent` (упрощённая запись в таблице).

**Важно:** Единовременно в сцене работает только то, что находится в bubble. Остальные — данные в памяти, не Entity в сцене.

### 20.2 Оценка нагрузки

Полная симуляция (bubble radius 50):
- Максимум ~50-100 NPC Entity одновременно в сцене
- Каждый с pathfinding, анимацией, AI-состоянием
- Это приемлемо для Godot 4

Глобальная симуляция (весь мир вне bubble):
- GlobalAgent — lightweight структура
- Глобальный тик запускается не каждый кадр, а по таймеру
- Обновляет только ключевые события (война, торговля, набег)
- Тысячи GlobalAgent в таблице — не проблема

### 20.3 Структура глобального мирового менеджера

```gdscript
# autoloads/world_simulation.gd
class_name WorldSimulation
extends Node

var global_agents: Dictionary  # agent_id -> GlobalAgent
var factions: Dictionary        # faction_id -> Faction
var settlements: Dictionary     # settlement_id -> Settlement
var active_conflicts: Array[Conflict]
var world_events: Array[WorldEvent]
var world_rumors: Array[RumorEntry]

var _global_tick_timer: float = 0.0
const GLOBAL_TICK_INTERVAL: float = 5.0  # секунды реального времени между тиками

func _process(delta: float) -> void:
    _global_tick_timer += delta
    if _global_tick_timer >= GLOBAL_TICK_INTERVAL:
        _global_tick_timer = 0.0
        _run_global_tick()

func _run_global_tick() -> void:
    _tick_factions()
    _tick_conflicts()
    _tick_caravans()
    _tick_economy()
    _propagate_rumors()
    _cleanup_expired_events()
    SignalBus.emit_signal("world_tick_completed")
```

### 20.4 SignalBus интеграция

Все A-Life события идут через SignalBus. Ни одна система не вызывает другую напрямую.

```gdscript
# signal_bus.gd — A-Life сигналы
signal settlement_status_changed(settlement_id: int, new_status: SettlementStatus)
signal faction_at_war(faction_a_id: int, faction_b_id: int)
signal faction_leader_died(faction_id: int, leader_id: int)
signal caravan_event(route_id: int, event_type: CaravanEventType, location: Vector2)
signal rumor_created(rumor: RumorEntry)
signal world_event_occurred(event: WorldEvent)
signal player_reputation_changed(world_rep: float, regional_rep: Dictionary)
signal npc_grudge_added(npc_id: int, player_action: String)
```

Подписка на эти сигналы позволяет любой системе реагировать на события мира без прямых зависимостей.

### 20.5 Сохранение состояния мира

Что сохраняется:

```gdscript
class WorldSaveData:
    var seed: int
    var play_time: float
    var world_tick_count: int
    
    # Дельты от начального состояния
    var destroyed_settlements: Array[int]
    var changed_faction_control: Dictionary  # settlement_id -> new_faction_id
    var dead_unique_npcs: Array[int]
    var faction_relation_deltas: Dictionary
    var world_events_log: Array[WorldEvent]
    
    # Состояние агентов (только уникальных и именованных, не фоновых)
    var npc_states: Dictionary   # npc_id -> NPCSaveState
    
    # Репутация игрока
    var player_world_reputation: float
    var player_faction_reputations: Dictionary
    var player_grudges: Array[int]  # npc_ids с кровной местью
    
    # Прогресс расследования
    var discovered_clues: Array[int]
    var known_rumors_by_player: Array[int]
    var narrative_flags: Dictionary
```

Заметно: фоновые NPC **не сохраняются индивидуально**. Они генерируются заново из seed при загрузке. Сохраняются только значимые изменения.

### 20.6 Catch-up симуляция при загрузке

```gdscript
func load_world(save_data: WorldSaveData) -> void:
    # 1. Применить seed-состояние
    _initialize_from_seed(save_data.seed)
    
    # 2. Применить дельты
    _apply_save_deltas(save_data)
    
    # 3. Вычислить отставание
    var ticks_to_simulate = _calculate_catchup_ticks(save_data.play_time)
    ticks_to_simulate = min(ticks_to_simulate, MAX_CATCHUP_TICKS)  # не более 7 дней
    
    # 4. Быстрая симуляция
    for i in range(ticks_to_simulate):
        _run_global_tick()
    
    # 5. Уведомить системы
    SignalBus.emit_signal("world_loaded")
```

# ЧАСТЬ XIII: ДИЗАЙН-ПРАВИЛА

## 21. Балансировка и дизайн-правила

### 21.1 Принцип органичности

**Правило 1: Каждое событие должно быть следствием чего-то**

Разбойники не нападают на деревню "потому что так написано в коде". Они нападают потому что:
- Их лагерь рядом
- У деревни низкий гарнизон
- Давно не нападали (клан накопил силы)

**Правило 2: Последствия должны быть видимы**

Если произошло важное событие — мир должен выглядеть иначе. Сожжённая деревня видна. Брошенный пост виден. Поле боя видно.

**Правило 3: Игрок не может быть центром всего**

Мир должен жить и без участия игрока. Деревни восстанавливаются сами. Фракции воюют сами. Торговля идёт сама. Игрок — участник, а не двигатель.

### 21.2 Принцип экономии симуляции

**Не симулируй то, что игрок не увидит**

Если событие не может быть замечено игроком — оно не нужно в детальной симуляции. Достаточно его последствий.

Плохо: Каждый торговый путь ведёт реальную Entity по карте (дорого, незаметно игроку)  
Хорошо: Процентная модель успешности маршрута, Entity появляется когда игрок рядом

**Максимум деталей в радиусе игрока, минимум вне его**

LOD — не только визуальный принцип, но и симуляционный.

### 21.3 Принцип читаемости

A-Life может быть сложным внутри, но **понятным снаружи**.

Игрок должен уметь:
- Посмотреть на политическую карту и понять кто с кем воюет
- Услышать слухи и составить общую картину региона
- Оценить опасность деревни по видимым признакам
- Предсказать поведение разбойников по их снаряжению и расположению

Непредсказуемость — хорошо. Непонятность — плохо.

### 21.4 Принцип истории через последствия

A-Life не рассказывает историю через кат-сцены. Он рассказывает её через состояние мира.

Игрок приходит в деревню и видит:
- Сожжённые дома на окраине
- Нервная стража у ворот
- Торговец с перебинтованной рукой
- На доске: "Пропали трое жителей"

Из этих кусочков складывается история. Игрок сам понимает что произошло — или спрашивает NPC.

Это дороже с точки зрения контент-дизайна, но бесценно для погружения.

### 21.5 Принцип доступности тайны

Детектив-нарратив строится так, что:

- Базовую историю (версия 1-3) можно пройти без глубокого исследования
- Полную историю (версия 4, тайный финал) требует серьёзного вовлечения
- Ни одна концовка не "неправильная" — каждая отражает реальный выбор игрока
- Реиграбельность создаётся новыми семенами, новыми свидетелями, новой конфигурацией фракций

## 22. Уникальные персонажи — 400+ лорных NPC

### 22.1 Категории уникальных NPC

400+ уникальных персонажей — это не просто цифра. Это живая история мира:

**Имперский двор (прошлое)**  
Бывшие придворные, министры, генералы. Разбросаны по миру после краха. У каждого — своя версия событий, свои интересы, своя судьба.

**Текущие лидеры**  
Короли бывших провинций, лорды замков, архиепископ, глава гильдии. Влиятельные фигуры с реальной властью.

**Искатели истины**  
Люди, которые тоже расследуют случившееся. Конкуренты или союзники игрока. Могут помочь или помешать.

**Свидетели**  
NPC, которые что-то видели или слышали. Их показания — ключи к тайне.

**Потерянные**  
Люди, чья жизнь была разрушена крахом империи. Истории о том, что значит жить в мире после катастрофы.

### 22.2 Роль уникальных NPC в A-Life

Уникальные NPC не просто стоят на месте. Они живут — перемещаются по определённым маршрутам, посещают разные поселения, реагируют на события мира.

Если война уничтожила их город — они бежали в соседний. Если их фракция захватила новую крепость — они там.

Это создаёт органичную охоту за NPC: игрок знает что нужно поговорить с бывшим советником императора — но тот перемещается по миру и нужно его найти.

## 23. Особые механики — дополнительные идеи

### 23.1 Дни и праздники

Интересная идея из анкеты: игровой календарь с особыми днями.

Предложение:
- **Обычные дни** — стандартная жизнь
- **Рыночные дни** — раз в несколько дней в городах, более активная торговля
- **Годовщина смерти императора** — особое событие мира, NPC говорят об этом, возможны уникальные квесты
- **Праздники фракций** — у каждой фракции свои. В праздник: меньше работы, больше таверн, особые события

Это добавляет глубину без сложности.

### 23.2 Длина игрового года

Вопрос из анкеты остался открытым. Предложение:

- 1 игровой день = 30 реальных минут (баланс между скоростью и погружением)
- 1 игровой год = 12 месяцев × 30 дней = 360 игровых дней
- В реальном времени: 360 × 30 мин = 180 часов геймплея = 1 год
- Средний геймплей до финала: ~50-80 часов = ~2 игровых сезона

Это означает: события разворачиваются в рамках половины-года игрового времени. Достаточно для ощущения времени без перегрузки.

### 23.3 NPC рядом с базой игрока

Если репутация игрока достаточно высокая и база существует достаточно долго — в её радиусе начинают появляться NPC:

- Торговец ставит временный лагерь
- Дезертир просит укрытия
- Крестьяне из разорённой деревни основывают лагерь

Это не полноценная механика основания поселения — но зачаток органичного сообщества вокруг игрока. Каждый пришедший — со своей историей.

## 24. Детальная архитектура GlobalAgent

### 24.1 Иерархия принятия решений (BHT — Behaviour Tree Lite)

Полноценное дерево поведения (Behaviour Tree) — тяжело для тысяч агентов. Для GlobalAgent используется упрощённая иерархия `BHT-Lite`:

Три уровня приоритетов:

```
PriorityLevel 1 — SURVIVAL:
  - Am I being attacked? → DEFEND/FLEE
  - Is my settlement under siege? → RESPOND_TO_SIEGE
  - Am I critically low on morale? → RETREAT

PriorityLevel 2 — FACTION_DUTY:
  - Do I have a war order? → EXECUTE_WAR_ORDER
  - Is there a trade assignment? → EXECUTE_TRADE
  - Is patrol scheduled? → PATROL

PriorityLevel 3 — AMBIENT:
  - Default daily routine by role
  - GUARD → patrol assigned area
  - MERCHANT → tend shop / travel
  - CIVILIAN → daily work pattern
```

Агент проверяет приоритеты сверху вниз. Первый выполнимый — выполняется.

Простота — намеренная. Не нужно симулировать сложные эмоции для фонового агента. Нужна предсказуемость и читаемость поведения.

### 24.2 Goal Stack — стек целей

У более важных NPC (именованные, уникальные) поддерживается `goal_stack` — стек незакрытых задач:

```gdscript
class NPCGoalStack:
    var stack: Array[NPCGoal]
    
    func push_goal(goal: NPCGoal) -> void:
        # Если цель того же типа — игнорировать
        # Если цель выше приоритетом — вставить в стек
        pass
    
    func pop_completed() -> void:
        # Убрать выполненную цель
        # Вернуться к предыдущей
        pass
    
    func current() -> NPCGoal:
        return stack.back() if not stack.is_empty() else null
```

Пример: торговец едет из A в B (`TRAVEL_TO_B`). По дороге на него напали (`DEFEND_FROM_ATTACK`). После атаки — возвращается к `TRAVEL_TO_B`. Стек не потерял контекст.

### 24.3 Детализация WorldEvent

### 24.4 Таблица распространения слухов

Слух не просто "создан и готов". Он распространяется постепенно, по сети поселений.

```gdscript
class RumorEntry:
    var rumor_id: int
    var base_event_id: int       # ссылка на WorldEvent
    var origin_settlement: int
    
    var current_spread: Array[int]  # settlement_ids где слух уже есть
    var spread_radius: int           # радиус в "прыжках" по сети
    var distortion_level: float      # 0.0 = точно, 1.0 = сильно искажён
    
    var original_text: String
    var distorted_variants: Array[String]  # варианты на разном расстоянии
    
    var created_tick: int
    var expires_tick: int    # слухи устаревают через N тиков
```

Алгоритм распространения на каждом глобальном тике:

```gdscript
func _propagate_rumors() -> void:
    for rumor in world_rumors:
        if rumor.spread_radius > MAX_RUMOR_SPREAD:
            continue
        
        # Найти соседние поселения
        var neighbors = _get_neighboring_settlements(rumor.current_spread)
        
        for settlement_id in neighbors:
            var spread_chance = _calculate_spread_chance(rumor, settlement_id)
            if randf() < spread_chance:
                rumor.current_spread.append(settlement_id)
                rumor.spread_radius += 1
                rumor.distortion_level = min(1.0, rumor.distortion_level + 0.1)
```

Шанс распространения зависит от:
- Есть ли торговый маршрут между поселениями (выше)
- Насколько важно событие (значимые распространяются быстрее)
- Время с момента события (свежие распространяются быстрее)

## 25. Детективная система — техническая реализация

### 25.1 Clue Graph — граф улик

Детектив-нарратив строится на `ClueGraph` — ориентированном графе знаний:

```
[Место гибели] → [Тип оружия] → [Класс убийцы]
                              ↘ [Редкий яд] → [Только одна гильдия]
[Свидетель A]  → [Видел человека в плаще]
[Свидетель B]  → [Слышал голос — женщина]
[Документ X]   → [Список визитёров к императору накануне]
[Документ Y]   → [Личные письма императора] → [Он что-то знал о демоне]
                                              → [Упоминание конкретного имени]
```

Каждая улика — `ClueNode`:

```gdscript
class ClueNode:
    var clue_id: int
    var clue_type: ClueType     # PHYSICAL / TESTIMONY / DOCUMENT / LOCATION
    var description: String
    var is_discovered: bool
    
    var discovery_condition: ClueCondition  # как обнаружить
    var leads_to_clues: Array[int]          # раскрывает другие улики
    var requires_clues: Array[int]          # требует других улик для понимания
    
    var points_to_version: int             # 0=ambiguous, 1-4=версия
    var weight: float                       # важность для расследования
```

### 25.2 Четыре версии — нарративные ветви

Каждая улика "голосует" за одну из четырёх версий через `points_to_version`. Игрок, собравший достаточно улик, видит какая версия набрала больше "голосов".

Но! Некоторые улики намеренно указывают в неправильном направлении. Это `false_clues` — улики, которые правдоподобны но ведут к неверной версии.

Зачем: мир создавал ложные следы (случайно или намеренно). Некоторые NPC сами верят в неверную версию и дают честные, но ложные показания.

Настоящая версия (4) раскрывается только при накоплении специфических улик, связанных с историей демона — они сложно найти, глубоко спрятаны.

### 25.3 Финальная сцена — как происходит раскрытие

Нет триггера "иди туда и произойдёт финал". Финал активируется когда:

1. Игрок накопил достаточно улик (порог по весу)
2. Игрок нашёл убийцу (уникальный NPC)
3. Игрок принял решение — убить / поговорить / предать суду

При убийстве убийцы без разговора: короткая финальная сцена с версией которую набрал игрок. Не полный финал.

При разговоре с убийцей (и достаточном количестве улик): убийца рассказывает больше. Открывается след к демону.

При следовании следу демона: секретная концовка.

### 25.4 Информация от NPC — система разблокировки

Уникальные NPC не выдают информацию сразу. Нужно:

- Повысить отношение (выполнить их квест, помочь)
- Иметь достаточную репутацию
- Иметь нужные улики (спросить правильно)

Это реализуется через `DialogueGate`:

```gdscript
class DialogueGate:
    var required_relation: int      # минимальное отношение
    var required_reputation: float  # минимальная репутация
    var required_clues: Array[int]  # нужные улики для этой темы
    var required_faction: int       # нужна принадлежность к фракции
```

NPC-разговор — не просто дерево диалогов. Это квалификационный фильтр. Ты должен заслужить информацию.

## 26. Фракционный ИИ — детальная логика решений

### 26.1 Дерево решений FactionTick

```
FactionTick:
│
├─ Оценка безопасности
│  ├─ Есть активная война? → военная логика
│  ├─ Враг у границы (< 3 поселений)? → готовность к обороне
│  └─ Мирное время → экономическая логика
│
├─ Военная логика (если в войне)
│  ├─ Военная мощь > противника? → наступление
│  ├─ Равна? → удерживать позиции
│  └─ Ниже? → запрос мира / отступление
│
├─ Дипломатическая логика (мирное время)
│  ├─ Есть casus belli против кого-то? → оценить риск войны
│  ├─ Кто-то слаб? → opportunistic aggression
│  └─ Нет поводов → торговля / усиление
│
└─ Экономическая логика
   ├─ Treasury низкий? → урезать армию / повысить налоги
   ├─ Treasury высокий? → расширить армию / строить
   └─ Нормальный? → поддерживать статус кво
```

### 26.2 Military Strength — абстрактный показатель

`military_strength` — не число солдат. Это абстрактная мощь, рассчитанная из:

```
military_strength = 
    (total_soldiers * avg_equipment_tier)
    + (fort_level * FORT_BONUS)
    + (morale_modifier * MORALE_FACTOR)
    - (active_wars_count * MULTI_WAR_PENALTY)
```

При расчёте исхода битвы:
```
attacker_strength vs defender_strength
+ randomness_factor (±20%)
+ terrain_modifier (в своём замке: +30%)
```

Простая формула, но дающая читаемые результаты.

### 26.3 Предательство внутри фракции

Предательство активируется при следующих условиях:
- Лидер непопулярен среди лордов (отношения < -20)
- Есть амбициозный претендент
- Внешняя угроза/давление или поражение в войне

Механика:
1. Отщепенец (unic NPC из списка лордов) объявляет независимость
2. Часть фракции переходит на его сторону
3. Начинается внутренняя война
4. Исход — либо предательство подавлено, либо раскол фракции

Для детектива важно: предательство могло быть связано с убийством императора. Некоторые лорды извлекли выгоду из хаоса.

### 27.3 Ворота — ночная механика

Ворота создают естественный ритм дня:

- **Днём**: ворота открыты, стражник проверяет входящих (диалог)
- **Ночью**: ворота заперты. Стук → стражник отвечает через ворота → впускает при хорошей репутации или за взятку
- **Во время тревоги**: ворота заперты всегда. Нужен специальный код/квест

Ночная механика ворот — первый барьер для разбойников. Прорыв ворот = событие `SIEGE_STARTED`.

## 28. Детальная модель репутации

### 28.1 Три уровня известности

**Уровень 0 — Анонимность**  
Репутация 0-15. Ты никто. NPC не знают тебя. Отношения нейтральные по умолчанию. Стражники не обращают внимания (ни хорошего, ни плохого).

**Уровень 1 — Региональная известность**  
Репутация 15-50 (региональная). В пределах региона знают твоё имя. Некоторые NPC слышали о тебе от торговцев.

**Уровень 2 — Фракционная известность**  
Репутация 50+ (фракционная). В пределах фракции ты персона. Доступны квесты высокого уровня. Лидер фракции может предложить встречу.

**Уровень 3 — Мировая слава**  
Мировая репутация 50+. О тебе знают во всём мире. Первая встреча с NPC может начаться с "Ты тот самый...". Разбойники T1-T2 не атакуют.

**Уровень 4 — Легенда**  
Мировая репутация 90+. Это редко. Слухи о тебе искажены до мифических масштабов.

### 28.2 Репутационные события

| Событие | Мировая рет. | Региональная рет. | Фракционная рет. |
|---|---|---|---|
| Убийство случайного NPC | -5 (если видели) | -15 | -20 |
| Убийство разбойника | +0 | +1 | +2 |
| Уничтожение лагеря разбойников | +5 | +10 | +15 |
| Спасение от осады | +10 | +25 | +30 |
| Убийство лидера клана | +8 | +15 | — |
| Победа в генеральной битве | +25 | +40 | +50 |
| Предательство союзника | -20 | -40 | -80 |
| Убийство лидера фракции (враг) | +15 / -30 | варьируется | +50 / -50 |

### 28.3 Влияние репутации на разбойников

Разбойники оценивают игрока прежде чем атаковать. Это не абстрактная цифра — это визуальная оценка:

```
aggressive_decision =
    base_aggression (по идеологии клана)
    - player_equipment_intimidation
    - player_world_reputation_factor
    + group_size_confidence
    + recent_success_bonus
```

Результат: разбойники в T1 снаряжении, видя игрока в T4+ с высокой репутацией, могут уйти. Или прокричать угрозу и отступить. Это настоящая игровая механика трусости.

## 29. Биомный A-Life

### 29.1 Как биом влияет на A-Life

Каждый из 13 биомов MiniLife имеет свой набор A-Life параметров:

| Биом | Фауна | Разбойники | Фракции | Особенности |
|---|---|---|---|---|
| Равнина | Олени, кролики | Средне | Все | Основной театр войн |
| Тёмный лес | Волки, медведи | Высоко | Редко | Скрытые лагеря |
| Болото | Кабаны, змеи | Высоко | Нет | Дезертиры, беглецы |
| Горы | Горные козлы | Средне | Форты | Засады на маршрутах |
| Пустошь | Стервятники | Очень высоко | Нет | Руины империи |
| Степь | Лошади, волки | Средне | Кочевники | Быстрые рейды |
| Руины (Проклятый лес) | ВорОны | Очень низко | Нет | Улики о демоне |
| Горный перевал | Редко | Высоко | Пограничные | Контрабандисты |

Биом определяет не только визуал, но и тактику выживания игрока.

### 29.2 Проклятый лес — особый биом

Проклятый лес — место где было что-то с демоном. Не "проклятый" в классическом фэнтезийном смысле — это зона исторической катастрофы.

A-Life в этом биоме:
- Разбойников нет (опасно, никто не базируется)
- Животные редкие, напуганные
- NPC отказываются входить или входят неохотно
- Руины с уликами о прошлом
- Ночью — уникальные атмосферные события

Это не сложная симуляция. Это нарративная зона с особой атмосферой.

## 31. Мир после империи — нарративный контекст

### 31.1 Один месяц после смерти

Игра начинается спустя ровно один месяц после гибели молодого императора. Почему важна эта точка:

- Первый шок прошёл. Всё знают что произошло (или думают что знают)
- Первые политические реструктуризации уже случились — провинции объявили независимость
- Ещё не все следы заметены — свидетели живы, документы не все уничтожены
- Мир не стабилизировался — хаос продолжается

Это идеальная точка для начала расследования: достаточно свежо, достаточно опасно.

### 31.2 Что изменилось за месяц (начальное состояние)

Через글로발глобальные тики, которые симулируются при первом запуске из seed:

- Несколько провинций объявили независимость (2-3 королевства уже сформированы)
- Имперская столица — в состоянии политической неопределённости (спорный город)
- Разбойнические кланы выросли из дезертиров и мародёров
- Торговые маршруты нарушены в 30-40% случаев
- Часть уникальных NPC уже мертва (первые жертвы хаоса)

Это не рандомный хаос — это детерминированное из seed начальное состояние с ощущением прошедших событий.

### 31.3 Имперские реликвии

В мире рассеяны артефакты старой империи:

- Личные вещи покойного императора
- Имперские документы, письма, указы
- Оружие имперской гвардии
- Символы власти (печати, медальоны)

Каждый такой артефакт:
- Имеет историю (откуда, чей)
- Может быть уликой в расследовании
- Имеет ценность для коллекционеров (НПС-коллекционеры платят хорошо)
- Некоторые фракции разыскивают конкретные реликвии (как символ легитимности)

Игрок, собирающий реликвии, автоматически попадает в детективный слой — реликвии указывают на людей и события.

## 32. Слои информации — как игрок узнаёт мир

### 32.1 Пять источников знания

**1. Прямые наблюдения (игрок видит сам)**  
Разрушенная деревня. Поле боя. Труп с особым клеймом. Это самый надёжный источник — игрок свидетель.

**2. Разговоры с NPC**  
Диалог как источник. Торговец рассказывает о состоянии дорог. Стражник упоминает о событиях в регионе. Требует инициативы игрока.

**3. Доски объявлений**  
Агрегатор публичных событий. Быстро, удобно, но поверхностно.

**4. Документы и записки**  
Глубокий источник. Дневник NPC, официальное письмо, старая карта. Требует исследования локаций.

**5. Подслушанные разговоры**  
Самый уникальный источник. Информация, не предназначенная для игрока. Разговор двух стражников. Перешёптывание купцов.

### 32.2 Качество информации

Не все источники равнозначны. Информация имеет `reliability_score`:

| Источник | Надёжность | Полнота |
|---|---|---|
| Прямое наблюдение | Высокая | Ограниченная (видно не всё) |
| Уникальный NPC (свидетель) | Высокая (если доверяет) | Высокая |
| Именованный NPC | Средняя | Средняя |
| Фоновый NPC | Низкая | Низкая |
| Доска объявлений | Средняя | Средняя |
| Документ | Высокая | Высокая |
| Слух (искажённый) | Низкая | Низкая |
| Подслушанный разговор | Высокая | Ситуативная |

Игрок, опирающийся только на слухи — придёт к неполной картине. Игрок, ищущий документы и свидетелей — получит настоящую историю.

## 33. Нарратив через игровой мир — примеры

### 33.1 Пример нарративного события

**Событие (глобальный тик):** Разбойничий клан "Серые Ножи" захватил деревню Брентвуд.

**Как игрок узнаёт:**

- Видит вороны над деревней (атмосфера)
- Входит в деревню — разрушенные дома, часть жителей убежала
- Оставшийся NPC рассказывает о нападении
- На доске объявлений соседнего города: "Деревня Брентвуд захвачена разбойниками"
- Торговец на дороге говорит: "Маршрут через Брентвуд опасен, лучше обходи"

**Пять слоёв подтверждения одного события.** Каждый независим. Вместе — полная картина.

### 33.2 Пример детективного нарратива

**Улика: В руинах имперского поста найдено письмо.**

Содержание письма намекает на встречу между высокопоставленным лордом и неизвестной личностью за неделю до смерти императора.

Что это означает:
1. Есть конкретный лорд (уникальный NPC) — потенциальный свидетель
2. Была встреча — с кем? Это ведёт к другой улике
3. Письмо датировано — это сужает временную картину событий

Игрок теперь знает: надо найти этого лорда. Лорд — живой NPC в мире. У него есть маршрут, он где-то находится. Возможно его фракция теперь враждебна. Возможно он скрывается.

Это не квест с маркером "найди NPC-X в локации Y". Это органичное расследование.

## 34. Интеграция с существующими системами Godot

### 34.1 Связь с SignalBus (существующая архитектура)

Существующая архитектура MiniLife строго следует принципу SignalBus. A-Life система — не исключение.

WorldSimulation никогда не вызывает:
- `CombatSystem.start_battle()` напрямую
- `QuestSystem.trigger_quest()` напрямую
- `FactionSystem.update_territory()` напрямую

Только через сигналы:
```gdscript
# WorldSimulation генерирует:
SignalBus.world_event_occurred.emit(event)

# CombatSystem слушает:
SignalBus.world_event_occurred.connect(_on_world_event)

# QuestSystem слушает:
SignalBus.world_event_occurred.connect(_on_check_quest_triggers)
```

### 34.2 DataRegistry — хранение статических данных A-Life

DataRegistry (уже в архитектуре) хранит:
- `faction_definitions[]` — начальные параметры каждой фракции
- `settlement_templates[]` — шаблоны поселений
- `npc_name_pools[]` — пулы имён для рандомайзера
- `rumor_text_templates[]` — шаблоны текстов для слухов
- `clue_definitions[]` — все улики детективной системы

Это чисто статические данные — не изменяются в игре. WorldSimulation читает их при инициализации.

### 34.3 SaveSystem интеграция

SaveSystem (существующий) расширяется для A-Life:

```gdscript
# В SaveSystem.gd добавляется:

func _save_world_simulation() -> Dictionary:
    return {
        "factions": WorldSimulation.serialize_factions(),
        "settlements": WorldSimulation.serialize_settlements(),
        "global_agents": WorldSimulation.serialize_key_agents(),  # только важные NPC
        "world_events": WorldSimulation.serialize_recent_events(MAX_EVENTS_TO_SAVE),
        "rumors": WorldSimulation.serialize_active_rumors(),
        "player_reputation": ReputationSystem.serialize(),
        "detective_progress": DetectiveSystem.serialize_clues(),
        "world_tick_count": WorldSimulation.world_tick_count,
    }

func _load_world_simulation(data: Dictionary) -> void:
    WorldSimulation.deserialize_factions(data.factions)
    WorldSimulation.deserialize_settlements(data.settlements)
    # ... и т.д.
```
